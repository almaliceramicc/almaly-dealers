# Дилерский портал «Алмалы-Керамик»

Каталог для оптовых покупателей, оформление заявки и панель продавца.

Портал — единственное место, где меняют фотографии и карточки.
Витрина QR-кодов ([almaly-tiles](https://github.com/almaliceramicc/almaly-tiles)) подхватывает эти правки сама.
Направление одно: портал → витрина. Правка, сделанная только на витрине, портал не меняет.

## Каталог портала

- `docs/data.json` — карточки: название, формат, покрытие, упаковка, паллета, остатки, список фото
- `docs/img/АРТИКУЛ/01.jpg` + `01_t.jpg` — фотографии портала (полный размер и миниатюра)
- `arts.txt` — какие артикулы вообще показывать. Строка удалена — карточки нет
- `sync_catalog.py` — ночью обновляет из Google-таблицы только товарные поля
  уже существующих карточек. Список фотографий не затирает
  (workflow «Обновление каталога», коммит с `[skip ci]`, зеркало витрины не запускает)
- Редактор каталога — вкладка «Редактор каталога» в панели продавца.
  Пишет фото и `data.json` одним коммитом. Кнопка **«Убрать карточку»** удаляет
  артикул из `arts.txt`: это и есть удаление карточки

## Зеркало витрины

После сохранения в редакторе workflow **«Зеркало витрины»**
(`.github/workflows/mirror.yml`) в течение нескольких минут:

1. Кладёт полные кадры `docs/img/АРТИКУЛ/01.jpg`, `02.jpg`, … (миниатюры `*_t.jpg` не копирует)
   в `photos/АРТИКУЛ/` витрины в том же порядке. Первое фото — обложка витрины.
   Старые файлы этой модели на витрине (в том числе PNG) заменяются.
2. Если изменился `arts.txt`, копирует его на витрину целиком.
   Убранный артикул исчезает из каталога и из `photos/`.
   Ночная «Пересборка каталога» на витрине обновляет только выгрузку Google-таблицы
   и заново собирает сайт. Файл `arts.txt` она не переписывает, поэтому
   удалённая карточка не возвращается.
3. Коммит на витрине называется «Зеркало с дилерского портала» и запускает
   уже существующую пересборку сайта и QR-кодов. В портал витрина ничего не пушит,
   взаимного цикла нет.

Ручной запуск того же workflow (кнопка Run workflow) только сверяет список карточек,
все фото подряд не перезаписывает.

Пока секрета из следующего раздела нет, workflow завершится ошибкой.
Сам портал при этом сохраняет правки как раньше.

### Один раз: секрет TILES_TOKEN

Токен, которым вы входите в редактор на портале, менять не нужно.
Он по-прежнему пишет только в `almaly-dealers` и в браузере.
Для переноса на витрину нужен второй токен. Его вставляют не в браузер,
а в секрет репозитория. В код токен не попадает.

1. Откройте GitHub под учётной записью, которой разрешено менять репозиторий
   `almaly-tiles` (обычно это владелец организации `almaliceramicc`).
2. Справа сверху нажмите свою фотографию → **Settings**.
   Внизу левого меню: **Developer settings** → **Personal access tokens** →
   **Fine-grained tokens** → **Generate new token**.
3. Заполните:
   - **Token name:** `Зеркало каталога`
   - **Expiration:** один год. Поставьте себе напоминание: когда срок выйдет,
     зеркало остановится, пока не выпустите новый токен и не вставите его в тот же секрет
   - **Resource owner:** `almaliceramicc`
   - **Only select repositories** и в списке отметьте только `almaly-tiles`
   - **Permissions** → **Repository permissions** → **Contents** → **Read and write**
   - Другие права не включайте
4. Нажмите **Generate token**. Скопируйте строку токена сразу:
   GitHub показывает её один раз.
   Если организация просит подтвердить токен, откройте уведомление GitHub
   (колокольчик или письмо) и нажмите **Approve**.
5. Откройте страницу секретов портала:
   <https://github.com/almaliceramicc/almaly-dealers/settings/secrets/actions>
6. **New repository secret**.
   - **Name:** `TILES_TOKEN` — латиницей, именно так, без пробелов и кавычек
   - **Secret:** вставьте скопированный токен
7. **Add secret**.
8. Проверка. Откройте
   <https://github.com/almaliceramicc/almaly-dealers/actions>,
   слева выберите **Зеркало витрины**, справа **Run workflow** → **Run workflow**.
   Зелёная галочка значит, что секрет подошёл.
   Если список карточек уже совпадает, в журнале будет «Нечего отправлять на витрину» —
   так и должно быть, пока вы не поменяете фото или карточку.

Зеркало пишет в витрину само. Отдельная правка репозитория `almaly-tiles` для этого не нужна:
ночная пересборка и раньше не трогала `arts.txt`, поэтому снятая карточка не вернётся.
Файл `almaly-tiles.patch` в этом репозитории — необязательное дополнение: новый текст
README витрины, пометка в её редакторе и удаление старых QR у моделей, которых уже нет
в каталоге. Записать его в `almaly-tiles` отсюда не получилось (нет права на запись).
Когда будете готовы, откройте тот репозиторий в Cursor и попросите применить
`almaly-tiles.patch` из портала. После этого файл можно удалить.

## Страницы

- `docs/index.html` — каталог: поиск, фильтры, остатки складов, бейджи новинок
- `docs/tile.html?a=АРТИКУЛ` — модель: галерея, характеристики, **ввод в м²** с пересчётом
  в целые упаковки, вес и склад отгрузки
- `docs/order.html` — оформление: позиции, данные заказчика, доставка и оплата,
  отправка заявки, упаковочный лист с номером заявки (печать/PDF)
- `docs/admin.html` — панель продавца: вход по логину и паролю. Вкладка «Заявки» —
  статусы, контакты дилера в один клик, печать листа, выгрузка CSV. Вкладка «Редактор каталога» —
  загрузка, удаление, порядок и обложка фотографий, кнопка «Убрать карточку»
  (вход по GitHub-токену). Те же фото и удаление карточки сами уходят на витрину QR

## Приём заявок

**Сейчас работает без сервера.** Дилер нажимает «Отправить заявку» — открывается WhatsApp менеджера
с текстом заявки и ссылкой вида `admin.html#o=…`, внутри которой лежит вся заявка. Менеджер открывает
ссылку, и заявка сама добавляется в панель со статусом «Новая»; журнал хранится в его браузере,
статусы и выгрузка CSV работают. Повторное открытие той же ссылки дубль не создаёт.

**Когда понадобится общий список для нескольких менеджеров** — разверните Google Apps Script
(5 минут, `apps-script/README.md`) и впишите адрес веб-приложения в `docs/config.js` → `ORDERS_API`.
Панель сама переключится на сервер: вход по коду, заявки приходят без ссылок.

## Дизайн

Единая дизайн-система в `docs/style.css`: переменные (цвета, шрифты, шкала текста и отступов,
радиусы, тени, уровни, анимации) и переиспользуемые компоненты — кнопки, поля, чипы, статусы,
карточки, плашки, пустые и загрузочные состояния. Отдельных «локальных» стилей на страницах нет.

- Палитра: тёплая бумага и известняк, графит как основной интерфейсный цвет,
  фирменный красный из логотипа — только акцент (знак, «Новинка», статус «Новая», счётчик заявки).
- Шрифты: Cormorant Garamond для крупных заголовков, Inter для интерфейса и чисел (табличные цифры).
- Логотип: знак-ромб `docs/assets/mark.svg` (он же вписан в шапку и фавиконки) и начертание
  ALMALI / CERAMIC текстом. Растровый файл логотипа в репозитории не нужен.
- Остатки и статусы дублируются словом, а не только цветом; красный не используется
  для обычного отсутствия товара — «Под заказ» нейтрален.
- Мобильные фильтры: те же элементы переезжают в нижнюю панель (одно состояние, не копия).
- Тема: кнопка солнце/луна в шапке всех страниц (`docs/theme.js`). По умолчанию берётся системная,
  выбор посетителя хранится в его браузере (`almaly_theme`). Тёмная тема — это только переопределение
  переменных в `:root[data-theme="dark"]`; упаковочный лист всегда печатается светлым.
- Учитывается `prefers-reduced-motion`, все интерактивные элементы не ниже 44 px.

Версии ресурсов проставляет `./bump.sh` — запускайте после правок CSS и JS.

## Настройка

`docs/config.js`:
- контакты компании: телефон, почта, WhatsApp менеджера (сейчас заглушки);
- `ADMIN_USERS` — логины и пароли продавцов. Сейчас временно `admin / admin`.
  Страница статическая, значения видно в исходном коде, поэтому это защита от случайных
  посетителей, а не настоящая: смените пару на менее очевидную, прежде чем раздавать
  адрес панели за пределами компании;
- `ORDERS_API` — адрес приёма заявок, если понадобится общий список на несколько менеджеров.
